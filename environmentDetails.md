# JobOne Platform — Environment & Codebase Architecture Details

**JobOne** is a full-stack, cross-platform job portal platform built for both **Web** and **Android (mobile app)**. It connects Jobseekers with Employers and features AI-assisted resume screening and candidate search.

---

## 📁 1. Codebase Architecture & Overview

### **Tech Stack & Structure**
* **Frontend (`/frontend`)**:
  * **Framework**: React 18 with Vite and React Router DOM.
  * **Styling**: Vanilla CSS, TailwindCSS, and Framer Motion for dynamic animations.
  * **Mobile / Desktop (Cross-Platform)**: Powered by **Tauri v2** (`/frontend/src-tauri`), which packages the Vite web application into a native Android APK and desktop application using the device's native webview.
  * **Authentication**: JWT token-based authentication stored in `localStorage`, along with Google OAuth (`@react-oauth/google`).
* **Backend (`/backend`)**:
  * **Framework**: Node.js & Express.js REST API.
  * **Database**: MongoDB with Mongoose ODM.
  * **File Storage**: AWS S3 (`@aws-sdk/client-s3`) for storing profile pictures, resumes, and employer verification documents.
  * **Email Service**: Brevo (formerly Sendinblue) REST API via `axios` for transactional emails, OTP verification, and notifications.
  * **AI Integration**: Google Gemini (`@google/generative-ai`) for AI-based resume parsing, candidate search, and chatbot assistant features.

## 🔐 2. Environment Variables (`.env`) Audit: Active vs. Unused/Legacy

Below is the exact audit of the credentials present in our backend and frontend `.env` files, distinguishing between what is actively required by the system versus legacy configuration leftovers.

### 🟢 **Actively Used Credentials (Required for the App to Function)**

#### **Backend (`/backend/.env`)**
1. **`MONGO_URL`**: The MongoDB connection string used in `configs/db.js` to connect the API to the database cluster.
2. **`PORT`**: The port number on which the Node/Express server runs (default: `5000`).
3. **`JWT_SECRET`**: A secret cryptographic key used across all authentication middlewares (`authorization.js`, `employercheck.js`) to sign and verify JSON Web Tokens (JWT) for user and employer sessions.
4. **`BREVO_API_KEY`**: The API key for Brevo (Sendinblue), used in `utils/sendEmail.js` and `utils/emailVerification.js` to send OTP emails and registration alerts.
5. **`EMAIL_USERNAME`**: The verified sender email address registered on Brevo (must match the account associated with the `BREVO_API_KEY`).
6. **`AWS_BUCKET_NAME`**: The name of our AWS S3 bucket where candidate resumes and employer documents are uploaded.
7. **`AWS_BUCKET_REGION`**: The AWS region where the S3 bucket is hosted (e.g., `ap-south-1`).
8. **`AWS_ACCESS_KEY_ID`**: The AWS IAM Access Key used by the SDK to authenticate S3 file uploads and reads.
9. **`AWS_SECRET_ACCESS_KEY`**: The AWS IAM Secret Key corresponding to the Access Key ID above.
10. **`GOOGLE_CLIENT_ID`** (or `Google_Client_ID`): Used by `OAuth2Client` in `controllers/userControllers.js` and `employerControllers.js` to securely verify Google Sign-In ID tokens sent from the frontend.
11. **`GEMINI_API_KEY`**: Used in `controllers/aiControllers.js` and `aiChatControllers.js` to call the Google Gemini AI models for smart resume screening and chatbot assistance.

#### **Frontend (`/frontend/.env`)**
1. **`VITE_GOOGLE_CLIENT_ID`**: Used in `src/main.jsx` inside `<GoogleOAuthProvider>` to initialize the Google Login popup on the frontend client.

---

### 🔴 **Unused / Legacy Credentials (Can be Safely Removed)**

These keys are currently present in the `.env` files from earlier testing or legacy setups (e.g., Nodemailer / old OAuth configs) and are **not used anywhere in the codebase**:
1. ❌ **`EMAIL_PASSWORD`**: Legacy nodemailer password (we now use the Brevo HTTP API).
2. ❌ **`EMAIL_USER`**, **`EMAIL_PASS`**, **`EMAIL_SERVICE`**: Old Nodemailer configuration leftovers.
3. ❌ **`Google_Client_Secret`**: Not required on our backend because we only verify ID tokens generated by the client using `OAuth2Client`.
4. ❌ **`Google_Redirect_URI`**: Not required for popup-based token verification.
5. ❌ **`Google_Project_ID`**: Not referenced in code.

## 🛠️ 3. Step-by-Step Guide to Generate Each Active Credential

### **A. MongoDB Database (`MONGO_URL`)**
1. Go to [MongoDB Atlas](https://www.mongodb.com/cloud/atlas) and create a free account or sign in.
2. Create a new **Cluster** (free tier is sufficient).
3. Under **Security > Database Access**, click **Add New Database User**, create a username and password, and assign **Read and write to any database** privileges.
4. Under **Security > Network Access**, click **Add IP Address** and select **Allow Access from Anywhere** (`0.0.0.0/0`) for development.
5. Go to **Database > Connect > Drivers** (Node.js), copy the provided connection string, and replace `<password>` with your database user password.

### **B. Brevo Email Service (`BREVO_API_KEY` & `EMAIL_USERNAME`)**
1. Go to [Brevo.com](https://www.brevo.com/) and sign up for a free account (allows 300 free emails/day).
2. Verify your email address during signup; this email will be your **`EMAIL_USERNAME`**.
3. Go to top-right profile icon > **SMTP & API** > **API Keys** tab.
4. Click **Generate a new API key**, give it a name (e.g., "JobOne API"), copy the key, and set it as **`BREVO_API_KEY`**.

### **C. AWS S3 Storage (`AWS_BUCKET_NAME`, `REGION`, `ACCESS_KEY_ID`, `SECRET_ACCESS_KEY`)**
1. Sign in to the [AWS Management Console](https://aws.amazon.com/).
2. **Create Bucket**: Search for **S3** > **Create bucket** > enter a unique name (this is **`AWS_BUCKET_NAME`**), select your region (this is **`AWS_BUCKET_REGION`**), uncheck "Block all public access" if public read access is required for profile photos, and create the bucket.
3. **Create IAM Credentials**:
   * Search for **IAM** > go to **Users** > **Create user**.
   * Name the user (e.g., `s3-upload-user`) > click Next.
   * Select **Attach policies directly** and attach `AmazonS3FullAccess` (for dev) or a scoped read/write policy for that specific bucket.
   * Once created, click on the user > go to the **Security credentials** tab > click **Create access key**.
   * Select **Application running outside AWS**, copy the **Access Key ID** (`AWS_ACCESS_KEY_ID`) and **Secret Access Key** (`AWS_SECRET_ACCESS_KEY`).

### **D. Google OAuth (`GOOGLE_CLIENT_ID` / `VITE_GOOGLE_CLIENT_ID`)**
1. Go to the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new Project or select an existing one.
3. Go to **APIs & Services > OAuth consent screen**: set User Type to **External**, fill in the app name, and save.
4. Go to **APIs & Services > Credentials** > click **Create Credentials** > select **OAuth client ID**.
5. Choose **Web application** as the Application type.
6. Under **Authorized JavaScript origins**, add your local dev URLs (e.g., `http://localhost:5173`, `http://localhost:1420`, `http://tauri.localhost`) and production domains.
7. Click **Create** and copy the generated **Client ID**. Paste this same string into both `VITE_GOOGLE_CLIENT_ID` (frontend) and `GOOGLE_CLIENT_ID` (backend).

### **E. Google Gemini AI (`GEMINI_API_KEY`)**
1. Go to [Google AI Studio](https://aistudio.google.com/).
2. Sign in with your Google account.
3. Click on **Get API key** in the left sidebar > click **Create API key**.
4. Select your Google Cloud project (or let it create a default one) to generate the key.
5. Copy the generated key and set it as **`GEMINI_API_KEY`** in the backend `.env`.

### **F. JWT Secret (`JWT_SECRET`)**
1. This does not require an external service. It is a random string used to encrypt user session tokens.
2. You can generate a secure random string by running this command in your terminal:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
3. Copy the output and set it as **`JWT_SECRET`** in the backend `.env`.
